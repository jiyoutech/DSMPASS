# Helper 账号授权边界

HMAC 只证明请求持有套件密钥，不证明目标 DSM 账号允许被 DSMPASS 管理。后端拥有数据库写权限，因此仅增加数据库查询不能隔离后端被入侵后的影响。

本次将两种检查同时放在 Helper 边界：

- 登录要求 `identity_id`、`login_source`、DSM 用户名对应同一个有效用户映射；身份源、外部账号、内部身份、登录许可和创建状态均须有效。`managed=0` 表示手工命名，不代表账号未受管，不以此字段判断授权。
- `/var/lib/dsmpass/account-policy.json` 由 root 独立保存用户名/UID 和群组名/GID。套件用户无法修改。管理员运行安装脚本时自动核对已有映射的普通账号，首次初始化同时登记符合条件的自定义群组；新账号/群组在 Helper 创建成功并重新查询系统身份后登记。
- 实际属于 `administrators` 的用户、UID 小于 1024 的系统账号、特权主组、系统群组、无效名称均禁止。读取系统账号信息有歧义或授权文件损坏时拒绝操作。账号改名或 UID/GID 改变后必须重新授权。
- 兼容 DSM 账号文件中的注释、空行及无关系统账号共用 UID；目标账号自身的 UID、目标群组自身的 GID 有别名歧义时仍拒绝。管理员组的 GID 别名同样按管理员权限检查。
- 登录写 shadow、永久改密、启用/修改/停用账号及群组成员操作均检查独立授权。检查在相应账号锁或全局写锁内再次进行。密码恢复不因撤销授权而被阻断。
- 群组移除使用固定 `/usr/syno/bin/synowebapi` 的 `SYNO.Core.Group.Member.remove` 接口，并检查 JSON 成功字段；DSM 没有 `synogroup --memberdel`。应用只提交需要移除的成员，不读取整组名单后覆盖其余成员。
- root 进程不直接打开套件可写的 SQLite 数据库。固定 Helper 二进制以套件 UID/GID、空附加组和清理后的环境启动查询子进程，使用只读连接；父进程限制时间和输出。数据库校验仍不是独立可信的身份证明，root 授权名单才限制其操作范围。
- 写操作改用 `scoped_*` 协议名，旧 Helper 无法接受新客户端请求，不会忽略新增授权字段后继续写入。恢复请求保留，便于完成已开始的恢复。

## 已有安装迁移

先按 [部署说明](go-dsm-binary-deployment.md) 停止旧 Helper、确认临时密码恢复并安装受保护的 Helper。管理员以 root 运行 `/var/packages/DSMPASS/target/setup-helper-sudo.sh`，脚本会自动核对当前映射并输出新增数量和跳过原因。终端与自动化环境均无需输入账号、编号或 `all`。安装脚本只登记授权，不修改密码、账号状态和群组成员。启动套件后可执行增量同步。

每次执行脚本都会检查活动身份源、外部身份和当前有效映射。其他身份源已成功创建或关联的普通账号可直接登记。钉钉的既往同步成功记录可能仅来自姓名匹配，安装器仍会核对 root 创建凭据或已验证邮箱。对于 `pending` 或 `failed`，安装器核对同一映射生效后的实际开通成功记录、root 创建凭据中的 UID，或 DSM 账号已有邮箱与通讯录内已验证且唯一的邮箱。既有创建凭据若不完整或 UID 不符则跳过。当账户缺少历史记录、创建凭据或可核对的邮箱，脚本会为活动的普通本地用户登记通讯录同步授权，同时固定 UID 及当前已纳入范围的部门 GID。增量同步可关联已有用户，并按有效映射同步已批准部门的成员关系。DSM 账号资料和启停状态保留原值。已有邮箱互相冲突、账号停用或 UID 有歧义时会输出跳过原因。通讯录同步产生的成功记录不会把该账号升级为可登录、改密或停用的账号。钉钉确认停用或离职时，已绑定的普通账户也可按下节规则停用。已有普通账号从仅同步部门转为统一登录与全量改密时，优先按下节自动核实归属。其他类型身份源仍可在下次执行脚本时核对新增映射。

自动登记范围限于主组为 `users`、UID 在 1024 至 65535 之间且 UID 唯一的本地用户，同时排除管理员及已知高权限服务组成员。已登记账号的 UID 有变化时保留原绑定。新版会保留明确撤销的用户记录。旧版撤销只删除记录，升级后首次执行脚本时，仍满足条件的旧账号可能重新获得授权。群组已有的选择与撤销继续生效。安装前可备份 root 授权文件，回退旧版 Helper 时使用相应备份。只有通讯录同步授权的用户写入新的 `directory_users` 字段，旧 Helper 无法读取该字段。

管理员执行脚本即批准当时可核实的映射，须使用可信套件及数据库。安装查询由套件 UID 的只读子进程执行，授权通过 root 私有文件原子保存。同一次读取或写入失败后可以重试。普通同步、登录和服务启动没有批量导入入口。

### 已核实的已有账号自动参与登录和全量改密

Helper 安装或升级时批量记录已有账号的有效映射，包括 DSM 用户名和 UID、身份源、稳定用户标识及来源已验证且唯一的邮箱。首次登录或日常同步时，Helper 读取该 DSM 账号已有的邮箱。两边匹配、账号有效且仍是同一个普通本地用户时，Helper 自动完成关联。管理员不用逐人授权。实际登录和全量改密均重新核对固定身份与当前有效映射。全量改密成功后，该用户的 DSM 和 SMB 使用新密码。增量同步沿用原有密码语义。

对由组织管理的钉钉身份源，DSM 管理员可在 NAS 上指定身份源，一次性把已有且唯一的普通账号映射设为登录和全量改密归属。使用身份源详情页 URL 中的 `source` 值替换下列示例标识。命令直接应用当前这批对应关系，无需逐人核实，也不会启动同步或写入密码。

```sh
sudo /usr/local/libexec/dsmpass/dsmpass-helper bind-dingtalk-logins SOURCE
```

加上 `--dry-run` 可只统计可关联数量。仅在组织将这批已有对应关系视为账号归属依据时运行。Helper 要求本机原先固定的员工 ID、身份源、DSM 用户名和 UID 全部一致。重名、冲突、已禁用或被撤销的账号，以及管理员账号会跳过。新出现的姓名不会加入这次授权；已建立的归属保留在 Helper 策略中。批量命令仅可由 DSM 管理员在本机发起。

若安装快照早于通讯录首次拉取，后续才出现的同名旧账号需要在映射就绪后批量刷新安装快照。已有部门同步记录、同名或者同步请求中携带的邮箱均不足以改变原密码。身份替换、多来源冲突、UID 变化、管理员和已撤销账号不参与这条自动关联路径。

钉钉旧记录如果只登记了部门成员关系，而且没有可核对的邮箱，员工扫码后，管理员可以在该身份源的「登录审计」展开失败记录，点击「核实登录归属」。核对员工 ID 后，将页面生成的确认码加到对应 DSM 用户的描述中，再点击「验证并保存」。确认码有效期为 15 分钟。Helper 会复核原有的身份源、员工标识、NAS UID 和当前登录映射，记录登录及改密归属。完成后员工直接重新扫码即可，保留数据重装也可沿用。

### 通讯录姓名与 DSM 账号的对应关系

钉钉、企业微信、飞书按身份源和员工 ID 沿用已保存的对应关系。新员工姓名唯一时自动匹配普通 DSM 账号，缺少的账号在同步中创建。多个员工同名且 NAS 没有原名账号时，按员工 ID 的稳定顺序分配数字后缀，并跳过已占用的名称。

如果多个员工对应同一个尚未分配的 DSM 原名账号，管理页面会展示员工 ID 和邮箱供选择。管理员选一次，系统核对原账号 UID 后保存归属，并自动开始增量同步，为其余同名员工编号。保留数据重装后，已保存的对应关系继续生效。已有登录绑定可以直接沿用；仅有通讯录映射的旧账号仍需通过已有凭据归属机制开通登录和改密。同步旧账号的部门成员关系时，Helper 还会检查已授权的部门范围。

### 钉钉同名用户的部门同步

启用钉钉通讯录后运行一次 root 安装脚本，安装器记录当前身份源和普通本地账号的 UID。钉钉通讯录姓名与 DSM 登录名一致、同一通讯录中姓名唯一且映射有效时，Helper 将现有账户关联到该身份源的稳定用户标识。以后在钉钉中加入其他已登记的普通部门，下一次同步就会向对应 DSM 群组添加这名成员。此前已经登记为仅通讯录授权的账号可以直接迁移。新建了钉钉身份源，或在 DSM 手工新增了需要复用的本地账号时，重新执行安装脚本即可刷新范围。

如果钉钉出现重名、标识被替换、已登记 UID/GID 变化或账号被撤销，会停止对应的自动加组。仅按姓名关联的账号在全量同步中保留 DSM/SMB 密码，密码操作日志显示跳过。启用缺失数据停用后，离开部门只停用 DSMPASS 的本地成员关系，NAS 上已有的组成员及相应共享权限会保留。启用身份源的「禁用缺失用户」后，钉钉企业账号状态明确为停用时，当前同步会停用已绑定的 NAS 账号。普通用户从组织通讯录消失时，需要启用缺失数据停用，并在全量同步前后均确认应用可见整个组织。目录范围不足、另有有效身份或仅调部门时，保留 NAS 账号。企业账号状态读取失败可检查钉钉应用的企业帐号状态查询权限。

旧版 Helper 无法读取新增的身份源、UID 和钉钉标识绑定，回滚时需要配套的 root 授权文件备份。

全新安装 Helper 时，安装器同时记录当时已有的普通 DSM 本地群组及其 GID。之后配置通讯录，首次开通部门会核对有效映射、组名和 GID，再沿用原组及共享文件夹权限。首次开通不会改动群组成员，后续同步按成员更新。系统组、套件组、目录服务组、GID 有歧义和已知的特权服务组不参与自动复用。本地组编号范围依据[群晖 GID 说明](https://kb.synology.com/en-sg/DSM/tutorial/UID_GID_reserved_by_Synology)。

旧版首次确认群组范围时，无参数脚本自动选择符合条件的普通本地群组并固定当时的 GID。同步开通仍要求有效部门映射。旧版没有记录撤销历史，首次建立范围时可能包含此前已移出的群组。已保存的空范围或部分范围会继续生效。需要首次手选群组时可显式运行 `setup-helper-sudo.sh --review-local-groups`，旧参数 `--reuse-local-groups` 也可继续使用。

### 在网页确认例外群组

在身份源的部门群组表中点击「网页授权」。已有有效映射且可自动沿用的群组会直接提示已授权。遇到旧版遗留群组、安装后手工创建的组或同名重建的组时，可按以下步骤办理。

1. 复制页面显示的短码。通过群晖网页打开「控制面板 → 用户与群组 → 群组」，编辑页面指定的普通本地群组。
2. 在组描述末尾用空格分开并粘贴短码，保存。如果描述空间不足，先保存原文，再临时替换描述。
3. 回到 DSMPASS 点击「验证并同步」。Helper 从 DSM 读取描述，核对实际组名、GID 和有效部门映射，成功后页面启动增量同步。常规增量同步开通该组时也会核对已保存的短码。授权完成后可恢复原描述。

授权码在 15 分钟内有效。过期或组编号变化后可在弹窗重新获取。撤销组授权会取消未完成的请求。管理后台不会收集 DSM 管理员密码或会话。该流程适用于已正常运行的新版 Helper。群晖的组描述由具有该组编辑权限的人通过 DSM 设置。[群晖群组管理说明](https://kb.synology.com/en-us/DSM/help/DSM/AdminCenter/file_group_desc?version=7)

对于迁移范围之外、以后需要额外接管的既有账号，仍可由管理员在 root shell 中执行以下命令，将示例名称替换为实际名称：

```sh
/usr/local/libexec/dsmpass/dsmpass-helper authorize-user alice
/usr/local/libexec/dsmpass/dsmpass-helper authorize-group engineering
```

该命令及安装迁移均不能通过套件的免密 sudo 控制入口或 socket 操作调用。迁移完成后，后台映射只能启用安装时已指定的群组及 GID。已有但未批准的用户账号会显示授权错误，不会自动重置密码或接管。

撤销使用 `revoke-user alice` 或 `revoke-group engineering`。撤销用户先保存拒绝策略，再恢复其尚未结束的临时密码；若锁正被占用或恢复失败，命令会报错，需要处理后重试。已经建立的 DSM 会话不会因此自动退出。

## 复查与验证范围

重点审查 `account_policy.go`、`authorization.go`、`group_commands.go`、`account_commands.go`、`sync_password.go` 和查询子进程 `cmd/helper/account_query.go`。测试覆盖身份/来源不匹配、失效映射、管理员组成员、UID/GID 改变、授权文件异常、旧协议拒绝、已有账号拒绝接管、新建账号登记和撤销后的恢复。

本地使用隔离账号文件、假 DSM 命令和临时 SQLite 验证，包含一次性迁移、重复映射、顺序变化、空数据、读取失败、并发初始化及撤销后不重新授权。Linux 交叉编译与 CI 不能代替各 DSM 版本和架构的实机验证；以对应 PR 中的实际测试记录为准。

后端被完全控制时，攻击者仍可请求操作已经登记的普通账号、创建新的普通账号以及修改受管群组成员；后端也持有业务数据。这项修改限制受影响的账号范围，不宣称后端失陷对 DSM 毫无影响。管理员后来授予受管账号额外共享权限时，这些权限也属于受影响范围。系统管理员并发修改账号不受本项目锁约束，保留 shadow 恢复时的身份与当前值检查。
