# Helper 自动升级

首次安装或从旧控制器迁移，需要管理员运行一次 `setup-helper-sudo.sh`。此后套件安装脚本通过受保护的 `helper-control.sh upgrade` 自动更新 Helper，无需每次 SSH 重新安装。未签名的源码构建仍可安装，但需要管理员明确执行初始化或更新。

自动更新只读取固定套件目录内的 `helper-release.json`、`helper-release.sig`、Helper 二进制和控制脚本。Helper 内置发行公钥，使用 Ed25519 校验包含版本、源码提交、构建时间、架构和两个文件摘要的清单；未签名、被篡改、架构不符及早于当前构建的包均拒绝。相同构建时间只允许与当前文件完全相同的幂等重试。校验通过前不停止运行实例、不写 root 文件；安装直接使用已校验的内存字节，避免校验后重新读取可写目录。

更新先完成临时密码恢复，将上一版程序、控制器、root 配置和 sudo 规则保存在 root 私有的 `/var/lib/dsmpass/previous-helper`，再原子替换程序并验证新实例健康状态。正常更新不修改账号授权和 root 配置。启动失败时尝试恢复原程序；如临时密码恢复失败，则保留现场并报告错误，不覆盖仍可能承担恢复任务的实例。断电或磁盘损坏仍可能需要管理员利用保留的备份恢复。

后台和 Helper 同时报告版本与源码提交。即使版本号相同，只要提交不一致，也会在管理页面明确提示。客户端在登录和同步操作前检查兼容性，避免向不匹配的 Helper 提交写操作；恢复接口也必须使用匹配版本。管理页的“重启并检查 Helper”会在发现版本不匹配时尝试签名更新。开发模式 `dev` 不强制发布版本匹配。

## 启动与旧日志迁移

Helper 先监听 socket 并响应经过身份验证的健康检查，再在后台迁移旧日志并执行首次密码恢复。旧控制程序的 10 秒存活检查因此无需等待全部磁盘操作；存活与可接收账号操作是两个独立状态。

初始化期间健康检查返回 `startup_ready=false`，所有非健康检查 RPC 返回 `HELPER_INITIALIZING`，不会提前修改 shadow 或 DSM 账号。管理页面显示初始化提示并自动刷新，无需反复重启。旧日志数量只影响首次就绪时间，不再占用启动存活检查的时间窗口。

无法确认所属账号的旧损坏日志仍会阻止就绪；原文件保留，`startup_error` 显示原因，修复后自动重试迁移。迁移完成后，单个账号的恢复错误仍由该账号自己的恢复索引拦截，其余账号正常使用，后台继续重试。此机制不会删除未恢复的密码记录，也不会绕过 DSM 账户锁。

## 发行签名

发行私钥不放进 Git、SPK 或 NAS。构建机通过 `DSMPASS_HELPER_SIGNING_KEY_FILE` 读取权限为 `0600` 的 Base64 Ed25519 seed 文件，也支持环境变量 `DSMPASS_HELPER_SIGNING_KEY`。构建工具确认私钥对应源码内置公钥后，分别签名 amd64 和 arm64 载荷。普通源码构建在没有密钥时仍然成功，输出未签名提示。

Release 工作流读取仓库 Actions secret `DSMPASS_HELPER_SIGNING_KEY`。维护者须将与内置公钥对应的 Base64 Ed25519 seed 配置到该 secret；工作流修改本身不会创建 secret。工作流先检查密钥是否存在、格式有效且公钥匹配，再构建两个架构的签名包；任一步失败均不进入发布步骤。构建脚本还会独立拒绝 GitHub Actions 标签构建缺少签名密钥，即使旧工作流遗漏传入 secret 也不会产生未签名正式包。

本地正式发行使用 `DSMPASS_REQUIRE_SIGNED_RELEASE=1 DSMPASS_HELPER_SIGNING_KEY_FILE=/受保护路径/ed25519-seed make package-spk`。缺少、无效或不匹配的密钥都会在编译前失败；普通分支 CI 和源码构建仍可不签名。配置 secret 后，应通过一次实际标签发行验证 Actions 到发布资产的完整链路；本地签名构建不能代替这项验证。

公钥轮换需要由原受信任密钥签名发布包含新公钥的 Helper，或由管理员明确重新初始化。丢失私钥会失去自动签名能力，应由维护者在本地之外保存安全备份。撤销已经签发的离线包没有在线撤销机制；构建时间仅阻止已经升级过的设备回退到较旧载荷。

## 验证范围

自动测试覆盖签名、错误公钥、清单篡改、二进制和控制器篡改、字段缺失、错误架构、降级、文件大小与符号链接、版本/提交不匹配以及回滚写入失败。真实升级、掉电行为和不同 DSM/CPU 的运行支持需实机验证，不能以交叉编译代替。
